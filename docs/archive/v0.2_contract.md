# NiCat v1 API contract — implementation subset

**Base:** `/api/v1/` | **IDs:** UUID | **timestamps:** UTC ISO 8601 | **Content:** JSON  
**Authentication:** server-managed session cookie; CSRF required for authenticated unsafe requests and explicitly enforced for anonymous register/login.  
**Format:** initial endpoints use REST Framework's standard errors; a global normalized `code/message/details/request_id` formatter is **not implemented** and remains in the backlog.

### Pre-submit payload
```json
{"id":"<attempt-uuid>","status":"in_progress","deadline_at":"2026-11-20T16:00:00+00:00","questions":[{"id":"<instance-uuid>","kind":"single_choice","prompt":"What is a stack?","marks":"2.00","options":[{"id":"<option-uuid>","text":"..."}]}]}
```
Never expose `private_key_snapshot`, `ChoiceOption.is_correct`, or unpublished rubrics in client endpoints.

### Result status
`graded_final` means final percentage and complete marks available. `grading_pending` means only `scored_marks`, `scored_possible_marks`, `ungraded_possible_marks` and per-item status available. Do not compute misleading final percentages while pending.

### Error conventions (current)
401/403 unauthenticated, 404 cross-owner, 409 state conflict, 400 invalid response. Plan to standardize all responses in a future API contract version.


### Reviewer marking response and audit (v0.2)

`POST review/grade-items/{id}/mark/` body: `{ "marks_awarded": "4.00", "rationale": "Covers FIFO and deletion order" }`.
`POST review/grade-items/{id}/correct/` body: `{ "marks_awarded": "4.50", "reason": "Rubric point omitted on initial assessment" }`.
Both return `grade_item_id`, `item_status`, `awarded`, `attempt_status`, `scored_marks`, `scored_possible_marks`, `ungraded_possible_marks` and nullable `final_percentage`. 403 is returned for non-reviewers; 409 for already-final or stale items. The queue returns private written answers and frozen rubric **only to authorized reviewers**.
